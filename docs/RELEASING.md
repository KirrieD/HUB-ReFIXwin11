# Выпуск 1.1.0

Репозиторий: https://github.com/KirrieD/HUB-ReFIXwin11. Эти команды ничего не публикуют:

```powershell
.\build.ps1 -Test
.\tools\Prepare-Release.ps1 -Tag v1.1.0
.\tools\Package.ps1
```

Prepare-Release пересчитывает SHA-256 двух готовых ZIP, записывает реальные будущие URL assets фиксированного репозитория и обновляет `artifacts/catalog.json` и `catalog/catalog.json`. URL заработают после публикации. Команда не создаёт commit/tag и не отправляет изменения. Package создаёт `bundle-files.json` с версией, точными путями и SHA-256; установщик проверяет список и хеши до изменения приложения. Старые ZIP и неизвестные файлы в существующей portable папке сохраняются, но не входят в архив. Удаление использует только проверенный список установленного комплекта и сохраняет прочие версии/данные. Package копирует только разрешённые файлы в `artifacts/HUB-ReFIXwin11` и создаёт `artifacts/HUB-ReFIXwin11-1.1.0.zip`; тесты и временные каталоги туда не входят. Обычная локальная сборка оставляет пустые PackageUrl и использует вложенные пакеты.

Перед выпуском проверьте portable ZIP на Windows 11, горячие клавиши, отдельное окно оформления и цикл NO → OFF → ON → OFF. Установку/удаление проверяйте отдельно под тестовым пользователем: эти скрипты меняют только его каталог, автозапуск HKCU и ярлык. Остановка HUB не останавливает утилиты; выключите их в HUB перед удалением, если это требуется. Удаление сохраняет заметки, темы и установленные модули.

Только после отдельного разрешения владельца отправьте исходники и тег `v1.1.0`. Tag-trigger workflow соберёт и проверит исходники, подготовит каталог, упакует portable архив, соберёт настоящий Setup с этим ZIP внутри и опубликует шесть assets через GitHub token: основной ZIP, `HUB-ReFIX-Setup-1.1.0.exe`, два ZIP модулей, `catalog.json` и `update.json`. **После успешной публикации assets** workflow получает актуальную main, создаёт отдельный checkout и коммитит от `github-actions[bot]` только `catalog/catalog.json`, копируя точные байты каталога этой CI-сборки, затем отправляет commit в main стандартным checkout token. HUB читает каталог из raw main. Локально подготовленный каталог не следует публиковать как каталог CI-пакетов: повторная компиляция и ZIP-упаковка могут изменить SHA-256 из-за временных меток.

Если защита main запрещает push токену workflow или ветка изменилась одновременно, последний шаг завершится ошибкой; опубликованные assets сохранятся, а старый каталог в main останется прежним. Скачайте **asset `catalog.json` именно этого опубликованного релиза**, без изменения скопируйте его в `catalog/catalog.json` и внесите через обязательный PR/проверки защищённой ветки. Не пересобирайте пакеты и не подставляйте каталог локальной сборки. Проверьте, что SHA-256 опубликованных ZIP совпадает с этим каталогом, и дождитесь доступности нового raw main. В случае ошибки синхронизации не объявляйте обновление готовым.

Единственный источник версии — публичная константа `ReFix.Shared.ProductInfo.Version` в `src/Shared/ProductInfo.cs`; сборка модулей, упаковка и Prepare-Release читают её. Версии обоих модулей и MinHubVersion совпадают с ней. Workflow принимает теги `v*`, а Prepare-Release требует семантический тег `vMAJOR.MINOR.PATCH`, точно совпадающий с константой. Для следующего выпуска измените константу и актуализируйте документацию; имена ZIP и список публикуемых assets вычисляются автоматически. Бинарники и скрипты не подписаны сертификатом издателя. SHA-256 подтверждает соответствие файлу из каталога, но не является подписью издателя.

## Portable, Setup и обновление HUB

`HUB-ReFIX.exe` — загрузчик без зависимости от Shared; основной интерфейс находится в `HUB-ReFIX.Core.exe`. В комплект также входят конфигурации обоих EXE, `ReFix.Shared.dll` и независимый `ReFix.UpdateHelper.exe`. Проверка `bundle-files.json` выполняется до запуска Core; неполный комплект показывает сообщение «Требуется настройка для корректной работы».

`Package.ps1` сначала создаёт точный portable ZIP, затем вызывает `Build-Setup.ps1 -Artifacts <каталог> -Payload <этот ZIP>`. Результат `HUB-ReFIX-Setup-1.1.0.exe` содержит тот же ZIP ресурсом `HubPayload.zip` и открывает установщик. Для проверки распаковки без установки, HKCU и запуска используйте `--extract-to <пустой изолированный каталог>`. Установщик сохраняет пользовательские данные и старые версии модулей, создаёт автозапуск/ярлык и `app/installation.json` с `Mode=Setup` и версией. Установленный HUB показывает «Все установлено». `tools/Install.cmd` остаётся совместимым способом установки полного portable комплекта.

После сборки Setup упаковка записывает `artifacts/update.json`: SchemaVersion, Version, PackageUrl, Sha256, SetupUrl, SetupSha256, Notes. Оба SHA-256 вычисляются по окончательным файлам. Метаданные, portable ZIP и Setup публикуются одним выпуском. Не пересобирайте ZIP после создания Setup или метаданных. Обычная локальная упаковка не публикует файлы: её URL станут доступны только после выпуска соответствующих assets.

HUB проверяет обновление однократно при запуске и по команде «Проверить обновления», используя метаданные опубликованного GitHub-релиза. Загрузка начинается только после выбора «Обновить»; «Отмена» оставляет текущее приложение без изменений. Проверенный помощник дожидается штатного выхода HUB, обновляет только разрешённые файлы и перезапускает загрузчик; при ошибке восстанавливает затронутые файлы. Маркер установленного приложения, неизвестные файлы, настройки и данные сохраняются. Первое обновление старой версии 1.0 требует ручного запуска Setup: в её бинарнике ещё нет этого механизма.
