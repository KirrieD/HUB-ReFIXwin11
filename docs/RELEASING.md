# Выпуск 1.0.0

Репозиторий: https://github.com/KirrieD/HUB-ReFIXwin11. На момент разработки удалённый репозиторий пуст, релизы не опубликованы. Эти команды ничего не публикуют:

```powershell
.\build.ps1 -Test
.\tools\Prepare-Release.ps1 -Tag v1.0.0
.\tools\Package.ps1
```

Prepare-Release пересчитывает SHA-256 двух готовых ZIP, записывает реальные будущие URL assets фиксированного репозитория и обновляет `artifacts/catalog.json` и `catalog/catalog.json`. URL заработают после публикации. Команда не создаёт commit/tag и не отправляет изменения. Package копирует только разрешённые файлы в `artifacts/HUB-ReFIXwin11` и создаёт `artifacts/HUB-ReFIXwin11-1.0.0.zip`; тесты и временные каталоги туда не входят. Обычная локальная сборка оставляет пустые PackageUrl и использует вложенные пакеты.

Перед выпуском проверьте portable ZIP на Windows 11, горячие клавиши, отдельное окно оформления и цикл NO → OFF → ON → OFF. Установку/удаление проверяйте отдельно под тестовым пользователем: эти скрипты меняют только его каталог, автозапуск HKCU и ярлык. Остановка HUB не останавливает утилиты; выключите их в HUB перед удалением, если это требуется. Удаление сохраняет заметки, темы и установленные модули.

Только после отдельного разрешения владельца отправьте исходники и тег `v1.0.0`. Tag-trigger workflow соберёт и проверит исходники, подготовит каталог, упакует portable архив и опубликует четыре assets через GitHub token: основной ZIP, два ZIP модулей и catalog.json. **После успешной публикации assets** workflow получает актуальную main, создаёт отдельный checkout и коммитит от `github-actions[bot]` только `catalog/catalog.json`, копируя точные байты каталога этой CI-сборки, затем отправляет commit в main стандартным checkout token. HUB читает каталог из raw main. Локально подготовленный каталог не следует публиковать как каталог CI-пакетов: повторная компиляция и ZIP-упаковка могут изменить SHA-256 из-за временных меток.

Если защита main запрещает push токену workflow или ветка изменилась одновременно, последний шаг завершится ошибкой; опубликованные assets сохранятся, а старый каталог в main останется прежним. Скачайте **asset `catalog.json` именно этого опубликованного релиза**, без изменения скопируйте его в `catalog/catalog.json` и внесите через обязательный PR/проверки защищённой ветки. Не пересобирайте пакеты и не подставляйте каталог локальной сборки. Проверьте, что SHA-256 опубликованных ZIP совпадает с этим каталогом, и дождитесь доступности нового raw main. В случае ошибки синхронизации не объявляйте обновление готовым.

Версия закреплена в скриптах сборки, упаковки и workflow; для следующего выпуска обновите их согласованно. Бинарники и скрипты не подписаны сертификатом издателя. SHA-256 подтверждает соответствие файлу из каталога, но не является подписью издателя.
