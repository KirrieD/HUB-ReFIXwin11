# Проверка 1.1.0

Windows 11, .NET Framework 4.8, C#5. Исходный самостоятельный QuietMixer сохранён. Установщики не запускались на настоящем профиле пользователя; системные фиксы не применялись.

Общий прогон: **92 проверки, 0 ошибок**, плюс дополнительные регрессии модулей. Проверены:

- Канонические физические клавиши, контекстные совпадения, конфликты ОС, сохранение старой регистрации при неудачном переназначении, повтор регистрации, освобождение клавиш и восстановление стандартных назначений без изменения автозапуска микшера.
- Уже открытые окна микшера и заметки реагируют на переназначение без потери громкости/текста; модельные окна управления и оформления остаются независимыми от прокрутки HUB.
- Миграция проверяет локальный пакет до остановки старого микшера, сохраняет старый автозапуск при ошибке, восстанавливает реально работавший процесс; кэш1.0 не подменяет новый вложенный пакет1.1.
- Независимый Bootstrap распознаёт отсутствующие/повреждённые файлы, runtime, каталог и пакеты; корректный Setup-маркер даёт сообщение «Все установлено».
- Подлинный Setup с внедрённым ZIP распакован командой `--extract-to` в отдельный каталог; все14 файлов совпали с SHA-256 манифеста. Эта команда не меняет реестр, автозапуск или ярлыки.
- Неизвестные совпадающие файлы при установке сохраняются в резервной копии. Ошибка копирования откатывает изменённые файлы.
- Пакет обновления: SHA-256, Windows-пути манифеста, обёрткаZIP, конфиги, каталог и пакеты, запрет выхода за корень, защита неизвестных файлов; rollback сохраняет данные и восстанавливает Setup-маркер.
- Парсеры сетевого каталога и метаданных обновления принимают UTF8 BOM из Windows PowerShell.
- PID, время старта и путь родительского процесса проверяются перед ожиданием; помощник обновления работает вне заменяемой папки.

Настоящая замена работающей пользовательской установки и будущий сетевой переход1.1→1.2 не запускались: проверена та же файловая логика на изолированных приложениях. Уже скачанная1.0 не имеет updater; первый переход выполняется новым ZIP или Setup. Публикация и работоспособность сетевых ссылок проверяются отдельно после GitHub Actions.
