# Проверка версии 1.0.0

Среда: Windows 11 build 26300, .NET Framework 4.8, локальный Roslyn C# 5. Проверено 25 октября 2026 года. Установка в настоящий профиль пользователя и публикация GitHub не выполнялись.

## Автоматические проверки

Полный `ReFix.Tests.exe`: 23 проверки, 0 ошибок. Проверяются нормализация и независимое копирование темы; прозрачность без изменения непрозрачности текста; кэширование изображения и непрерывное кадрирование; сохранение и внешние изменения темы, в том числе непрерывное движение ползунка; пользовательский IPC и очистка собственного состояния; проверка манифеста, SHA-256, ZIP traversal, повреждённого файла; сохранность старой версии при отказе переименования; атомарный каталог и конкурентное чтение; реальный цикл установленного QuickNote OFF → ON → показ → OFF; отказ обновления работающего модуля; устаревший PID; немодальный редактор, общие цвета в двух окнах и остановленный таймер скрытого HUB.

`tools/Build-Modules.ps1 -Test`: проходят дополнительные проверки прозрачной поверхности, alpha, свечения, размытия и углов обоих модулей, сохранности регуляторов микшера при смене темы, меню, XAML и сохранения заметки. Исходный отдельный QuietMixer не изменён.

Дополнительно воспроизведена и устранена блокировка файла темы во время атомарной записи. Чтение разрешает замену файла; запись имеет ограниченные повторы, а постоянный отказ виден в интерфейсе. Регрессии проверяют восстановление после временной блокировки без дополнительного Save и прекращение повторов при постоянном отказе.

Все проверки работают с изолированными каталогами в `artifacts`. Проверка пользовательского named pipe выполнялась вне ограниченной песочницы, поскольку та запрещает соединения даже с каналом текущего пользователя. Проверки не включают автозапуск, не устанавливают HUB и не применяют системные исправления.

## Ресурсы и интерфейс

В режиме `--background` до первого открытия окна: рабочий набор 43.6 MiB, private bytes 15.2 MiB; за 10 секунд ожидания счётчик CPU процесса не увеличился (0 ms). Это измерение на этой машине, а не обещание нулевого потребления на всех ПК. После первого открытия WPF остаётся загруженным, поэтому память увеличивается. Скрытые окна останавливают обновление статусов; сеть не опрашивается автоматически.

Интерфейс лениво загружается поверх лёгкого WinForms-трея. При открытии WPF-окон используется modeless keyboard interop. Основное окно и отдельный редактор отрендерены и визуально проверены в системной и пользовательской темах. Скриншоты находятся в локальном `artifacts/previews*` и не включаются в установочный архив.

## Независимая проверка кода

Исправлены найденные существенные проблемы: ошибочный откат пакета при отказе резервного переименования; конкурентное чтение каталога; неполная прозрачность/свечение/размытие модулей; задержка передачи темы до окончания перетаскивания. После изменения фонового загрузчика выполнена отдельная проверка его показа, скрытия, завершения и keyboard interop. Ошибка первого создания интерфейса записывается в журнал и завершает HUB, чтобы следующий запуск начинался с чистого состояния.

## Пределы проверки

Трей, горячая клавиша и переключение внешних приложений используют стандартные Windows API; интеграция с нестандартными оболочками требует проверки на конкретном ПК. Скрипты установки/удаления проверены по синтаксису и области изменения файлов, но не запускались на настоящем профиле. GitHub изначально пуст: реальный удалённый сценарий загрузки можно проверить после публикации Releases и точного каталога. Локальные вложенные пакеты проверены и доступны без сети. Готовых системных фиксов нет: реализован контракт их установки и проверки, а не произвольные изменения Windows.
