# ReFix.Shared SDK

Build with C# 5 and the Windows .NET Framework 4.8 reference assemblies: System, System.Core, System.Web.Extensions, WindowsBase, PresentationCore, PresentationFramework. No packages are required. Reference ReFix.Shared.dll from a separate module executable.

## Data and themes

`Paths.Root` resolves REFIX_DATA_ROOT on each access, otherwise `%LOCALAPPDATA%\ReFIXHub`. `Paths.ThemeFile`, `Paths.Modules`, and `Paths.State` derive from it; `Paths.Ensure()` creates those directories. Set the override before creating stores or runtimes, and retain it for their lifetime.

`ThemeProfile` has string Mode (`System`/`Custom`), eight `#RRGGBB` palette strings including Tertiary, BackgroundOpacity (0..1), GlowOpacity (0..1), GlowRadius (0..40), CornerRadius (0..24), FontSize (11..20), ImagePath, ImageOpacity (0..1), ImageBlur (0..30), ImageFit (`UniformToFill`/`Uniform`/`Fill`), and ImageX/ImageY (0..1). `Normalize()` clamps ranges and replaces malformed values; NaN/infinity revert to defaults. `Clone()` returns an independent profile. `Resolve(profile)` returns a normalized copy, deriving light/dark palette, accent and high-contrast colors in System mode. Background alpha affects the background only; text remains opaque.

`ThemeStore(root)` loads `theme.json`; `Current` returns a copy. `Save(profile)` publishes a normalized copy to Current and Changed immediately, and schedules a one-shot write 100 ms after the first pending change. Further edits before that write update its payload without postponing it, so continuous dragging propagates across processes about ten times per second. Disk persistence uses a unique temporary file and atomic replacement. Dispose flushes the final pending save. Readers use ReadWrite/Delete sharing so an old open snapshot does not block atomic replacement. A failed write gets at most five one-shot retries, 100 ms apart; after that no background retry runs until a new Save. `LastError` (string, null on success) exposes write failures and Changed fires when the error changes or clears. Dispose makes one final synchronous flush attempt and propagates failure to its caller. Invalid/incomplete external JSON retains the last valid profile. FileSystemWatcher and Windows user preference events update consumers without idle timers. `Changed` runs on a thread-pool thread; marshal to the WPF Dispatcher. Dispose stores on shutdown.

`ImportBackground(path)` accepts one frame, at most 20 MiB, 8192 pixels per dimension and 32 million pixels in total. It copies bytes under `root/assets/<SHA256>.img`; decoding identifies the image format independently of the extension. Unsupported, multi-frame or malformed images throw. It never changes the profile by itself: assign the returned path and save.

`ThemeApplier.Apply(window, profile)` resolves the profile and replaces window resources `Hub.Background`, `Hub.Surface`, `Hub.Foreground`, `Hub.Muted`, `Hub.Tertiary`, `Hub.Accent`, `Hub.Border`, `Hub.Glow`, `Hub.Image`, `Hub.Corner`, `Hub.FontSize`, plus `Hub.ImageBlur`. Windows use dynamic resource bindings so replacements take effect. Frozen image decoding is bounded to a 1920-pixel longest side and cached by absolute path, modification time and file size, with at most two cached entries shared across windows. UniformToFill crops continuously through relative Viewbox coordinates using the target window aspect ratio and ImageX/ImageY; Uniform positions a fitted image through relative Viewport coordinates. Reapply on window resize to recalculate fit. Callers layer background/image Borders and apply a BlurEffect of `Hub.ImageBlur` to the image layer only; apply root DropShadowEffect from resolved Glow, GlowOpacity and GlowRadius. The helper never sets Window.Opacity. `ThemeApplier.ColorBrush(hex)` returns a frozen solid brush.

## Process control protocol 1

`MixerLayoutProfile` и `MixerLayoutStore` хранят размеры микшера отдельно от общей темы в `mixer-layout.json`. Изменения распространяются через события и FileSystemWatcher; скрытое окно не запускает опрос аудио. Общая палитра, включая `Hub.Tertiary`, продолжает действовать при отдельной настройке геометрии микшера.

Construct `ModuleRuntime(id, show, stop)` and call `Start()` after initializing the module. IDs match `[a-zA-Z0-9][a-zA-Z0-9_-]{0,63}`. Callbacks run on the runtime worker thread; marshal UI operations to the Dispatcher. `stop` should request application shutdown; dispose the runtime during shutdown. All resources are event/blocking driven with no recurring idle work.

Always use `ModuleRuntime.PipeName(id)`: it returns `ReFIXHub.<current Windows SID>.<root SHA256>.<id>`. The overload `PipeName(id, root)` accepts an explicit data root for hosts; the single-argument helper uses Paths.Root. The scope is lowercase SHA256 of UTF-8 `Path.GetFullPath(root).TrimEnd(directory separators).ToUpperInvariant()`, isolating test sessions while treating Windows path casing/trailing separators consistently. The local byte-mode duplex named pipe grants access only to that SID, using a protected ACL. Connect as the same user. Send a single ASCII command followed by LF (CRLF accepted): `status`, `show`, or `stop`. Commands are limited to 256 bytes and a total read deadline of 1500 ms; reply writes have a 1500 ms deadline. Read one UTF-8 JSON line, then close the connection. Reconnect per command. Hosts should bound connection/read waits independently.

`status` replies with `id`, `state: "ON"`, `pid`, `startedUtc` (process StartTime.ToUniversalTime().Ticks encoded as a decimal string), `protocol: 1`, `executablePath` (absolute main executable path), and an opaque `instance` token. Parse startedUtc as Int64 UTC ticks. `show`/`stop` reply `{"ok":true}` and then invoke the callback; acknowledgement means accepted, not completed. Unknown commands reply `{"ok":false,"error":"unknown command"}`.

State at `<Paths.State>/<id>.json` has the same identity payload. It is evidence of a claimed process, not liveness. Verify PID, exact process start UTC ticks and installed executable path, then obtain matching pipe status before presenting ON. An exclusive `<id>.json.lock` file handle prevents duplicate runtimes from publishing or deleting each other's state. Lock files may remain empty after shutdown; their existence has no state meaning. Dispose atomically excludes a new publisher while checking its instance token and deleting its own JSON. Crashes leave stale JSON, which the host must treat as OFF when identity/liveness fails. Hosts must not delete live runtime state.

## Verification

`tests/SharedTests.cs` exposes `SharedTests.Run(Action<string,bool>)`. Compile with `SHARED_TEST_RUNNER` for a standalone runner. Put ReFix.Shared.dll beside it. Tests exercise normalized ranges, clone isolation, hidden WPF image cache reuse, continuous pan, background-only alpha, throttled persistence during continuous edits/disposal flush, external updates, malformed files/images, oversized images, current-user pipe commands, process identity, duplicate runtime refusal and replacement-state preservation. All test data uses a unique directory beside the runner and is removed afterward. Restricted desktop sandboxes may block even same-process pipe clients; run the isolated suite with native IPC access.
