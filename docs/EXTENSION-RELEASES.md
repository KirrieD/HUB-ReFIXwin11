# Независимые выпуски расширений

Версия HUB задаётся в ProductInfo.cs, версии расширений и минимальная совместимая версия HUB — в ModuleVersions.cs. При правке одного расширения повышайте только его версию.

Например, тег quick-note-v1.6.0 запускает сборку только «Быстрой заметки». Workflow публикует ZIP этого расширения, обновляет только его запись в каталоге main и оставляет основной релиз HUB последним в API обновлений. Пользователь получает пакет через «Обновить» на карточке расширения. Выпуски с разными тегами запускайте последовательно.

Локальная проверка выбранного расширения:

```powershell
.\build.ps1 -OnlyModule quick-note
.\tools\Build-Modules.ps1 -Only quick-note -Test
.\tools\Merge-ModuleRelease.ps1 -Tag quick-note-v1.6.0 -Candidate artifacts/module-catalog.json -Catalog catalog/catalog.json -Output artifacts/catalog-release.json
```

Обычный тег HUB по-прежнему даёт ZIP и Setup. Для неизменённых модулей он загружает уже опубликованные пакеты и сверяет SHA-256. Внутренние имена двух ZIP в portable архиве используют версию HUB, чтобы старые обновляторы продолжали распаковывать пакет. Новая версия HUB читает реальную версию каждого модуля и проверяет хеш перед использованием архива. Независимый выпуск расширения не публикует ZIP HUB, Setup или update.json.
